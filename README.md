# MUFCA Bot Client (Android)

Тонкий нативный клиент к тому же бэкенду, что уже работает на вебе:
WebView-обёртка вокруг веб-дашборда (`mufca-bot/web`) + нативный приём
push-уведомлений через Firebase Cloud Messaging — сигналы и TP1 приходят,
даже когда приложение закрыто, без Discord.

## Что где

```
app/src/main/java/com/mufcabot/app/
├── MufcaApp.kt                      # notification channel при старте
├── Prefs.kt                         # зашифрованное хранилище server URL + логин/пароль
├── ApiClient.kt                     # 2 нативных HTTP-вызова: тест подключения, регистрация FCM-токена
├── SettingsActivity.kt              # экран первичной настройки (server URL, Basic Auth)
├── MainActivity.kt                  # WebView-обёртка вокруг дашборда, deep-link по тапу
└── MufcaFirebaseMessagingService.kt # приём push, показ уведомления
```

Всё остальное (Status/Chart/History/Settings) — тот же React-дашборд, что и в
браузере, просто открытый внутри WebView. Ничего не дублируется.

## 1. Firebase — обязательные шаги перед сборкой

Ты уже создал Android-приложение в Firebase Console (`com.mufcabot.app`, видел
на скрине). Осталось два файла:

### google-services.json (в Android-проект)
На той же странице Firebase Console, где ты брал App ID — кнопка
**`google-services.json`**. Скачай и положи:
```
mufca-android/app/google-services.json
```
Без этого файла сборка упадёt на шаге `google-services` plugin с понятной
ошибкой — это ожидаемо, просто положи файл.

### firebase-credentials.json (на сервер бота, НЕ в Android-проект)
**Project settings → Service accounts → Generate new private key** — это
для бэкенда (Python), не для приложения. Положи на TrueNAS в тот же volume,
где `signals_history.json`, под именем `firebase-credentials.json`. Подробности
были в прошлом ответе по бэкенду — коротко: путь берётся из переменной
`FIREBASE_CREDENTIALS_PATH` в `.env` бота.

**Оба файла — секреты, никогда не коммитить в git** (уже в `.gitignore`).

## 2. Открыть в Android Studio

```
File → Open → выбрать папку mufca-android
```

В проекте **нет `gradle-wrapper.jar`** (бинарный файл, который я не могу
собрать без локального Gradle/сети до services.gradle.org). Android Studio
сама предложит его досоздать при первом открытии — просто нажми "OK"/"Sync
Now" на всплывающем предложении. Если не предложит сама:
**File → Sync Project with Gradle Files**.

Первая синхронизация скачает Gradle 8.7 и все зависимости — минуты 2-5 в
зависимости от интернета.

## 3. Собрать и запустить

- **Debug-сборка на подключенный телефон/эмулятор**: зелёная кнопка ▶ Run в
  Android Studio.
- **Release APK** (чтобы поставить на телефон без Android Studio):
  `Build → Generate Signed Bundle / APK` → APK → создай свой keystore (один
  раз, Android Studio проведёт по шагам) → release.

## 4. Первый запуск на телефоне

При первом открытии приложение попросит:
1. **Server URL** — твой домен дашборда (например `https://mufca.home.pvt.ge`)
2. **Username / Password** — те же `WEB_USERNAME`/`WEB_PASSWORD`, что в `.env`
   бота

"Save and connect" делает тестовый запрос к `/api/config` — если сервер не
отвечает или креды неверны, скажет прямо тут, до перехода на дашборд.

После этого:
- откроется WebView с дашбордом — там будет **свой** отдельный экран логина
  (тот же, что в браузере) — залогинься там один раз, дальше сессия
  сохраняется между запусками приложения
- в фоне зарегистрируется твой телефон для push-уведомлений

Настройки (server URL/креды) можно поменять позже через ⋮ → Settings в
приложении.

## Как это работает: два независимых логина

Тебе нужно будет ввести одни и те же логин/пароль **дважды** — это осознанно,
не баг:

1. **Нативный экран настройки** (при первом запуске) — эти креды использует
   только Kotlin-код для одного вызова: регистрации FCM-токена на бэкенде
   (`POST /api/devices/register`), чтобы push доходили. WebView в этом не
   участвует.
2. **JS-логин внутри WebView** — точно такой же, как в браузере на компьютере,
   для всех обычных действий с дашбордом (Status/Chart/History/Settings).

## Push-уведомления: как долетают и куда ведут при тапе

Бэкенд шлёт **только data-only** FCM-сообщения (не гибрид notification+data) —
это осознанное решение, не самое очевидное, поэтому поясню: гибридные
сообщения при свёрнутом/убитом приложении Android показывает **сам**, минуя
код приложения — а значит без нужных данных (какая пара/таймфрейм), и тап по
такому уведомлению просто открыл бы приложение на дефолтном экране. Data-only
гарантирует, что `MufcaFirebaseMessagingService.onMessageReceived()`
вызывается всегда, при любом состоянии приложения, и уведомление строится
самим приложением с правильным deep-link.

Тап по уведомлению → открывает `MainActivity` → после загрузки WebView
вызывает `window.mufcaOpenSignal(ticker, tf, tab)` (хук в `App.jsx` на
веб-стороне) → дашборд сам переключается на нужную вкладку/пару. Если ты ещё
не залогинен в WebView-сессии — просто откроется обычный экран логина, без
ошибок, автопрыжок тихо не сработает (best-effort, ничего не ломает).

## Известные ограничения

- **minSdk 24** (Android 7.0+) — покрывает практически все актуальные
  устройства.
- Иконка приложения — простой векторный рисунок (тёмный квадрат + янтарный
  круг + "M"), не полноценная adaptive-иконка с отдельными слоями. Если
  захочешь красивую — дай знать, можно сделать отдельно через
  Image Asset Studio в самой Android Studio (Right-click `res` → New → Image
  Asset).
- SSL: в debug-сборке самоподписанные сертификаты принимаются (для локальных
  тестов без нормального TLS), в release — нет. Если у тебя Cloudflare Tunnel
  с настоящим сертификатом (обычно так и есть), это не имеет значения.
